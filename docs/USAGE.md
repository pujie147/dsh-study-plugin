# 使用手册（学习区 study-work）

本手册面向使用者。学习区帮你管理多个「学习目标」：每个目标由会话 AI 联网调研产出课程草案，你批准后按自然章节生成讲义，每章在**独立会话**中学习与多轮问答。

## 1. 入口

左侧栏底部有 **「📚 学习区」** 徽标（侧栏收起时是圆形 📚 图标），点击展开浮动面板；徽标上的数字 = 正在调研/待批准/学习中的目标数。面板 2.5 秒自动刷新。

## 2. 面板操作

| 按钮 | 作用 |
| --- | --- |
| ＋ 添加学习目标 | 填写 主题 / 目标水平 / 附加要求 → **「✓ 创建并调研」**：先建文档，自动打开该目标专属会话，会话 AI 联网调研（5–10 章草案，按自然结构，不按学时）。完成后自动变为「待批准」 |
| 📄 打开会话 | 切换到该目标的**总会话**——也就是产出课程草案的那个会话（反复点都回到同一个会话）。只有它从未建立或已被销毁时，才在目标工作区新建一个并把新 id 记回 `goal.json` |
| ▶ 开始调研 / 🔁 重新调研 | 「调研中」状态下的派发口。chip 显示**「待调研」**= 目标只建了档、会话还没收到过指令（从聊天创建的目标都是这种），点「▶ 开始调研」才会真正开始联网调研；显示**「调研中…」+ 派发时间** = 指令已发出，等它写草案即可，久无产出可点「🔁 重新调研」重发 |
| ✓ 批准 | 批准草案 → 章节清单生成（每章状态「待生成」） |
| 重新调研 | 退回草案并清空旧草案文件，回到「调研中」 |
| 生成讲义 | 向目标总会话发送该章讲义撰写任务；文件写好后自动「讲义就绪」 |
| 继续生成 | 讲义停在「生成中」且文件未产出时点击：若文件其实已生成会直接标记就绪；否则重发任务。若会话未在工作，会退回「待生成」并提示你先打开目标会话再点「生成讲义」 |
| 📖 开始学习 | 为该章**创建独立章节会话**并进入（每章一个，已建过则直接打开） |
| 📤 导出 zip | 把该目标打成 zip（目标全部内容 + 该工作区全部会话 + 会话引用的图片），落在 `study-work/exports/` 并自动切到「📦」视图可下载 |
| 🔗 重新绑定会话 | 修复入口：重建该目标的工作区登记并把 `goal.json` 里记录的会话挂回工作区分组（迁移/重启后会话没出现在分组里时点它） |
| 📦（面板顶部） | 导出包视图：包列表（大小/时间）+ ⬇ 下载 + 删除；下面填 zip 路径 → 选模式（默认「⤴ 覆盖」）→「🔍 预览这个包」→「✓ 确认覆盖导入」 |
| 删除 | 仅标记删除（数据文件保留） |

## 2b. 导出与导入（换机器 / 备份 / 覆盖式同步）

**导出**：目标行「📤 导出 zip」（或聊天里说「把 XX 目标导出」）。产物 = `~/.dsh/study-work/exports/study-goal-<goalId>-<时间戳>[-n].zip`（同一秒连点不会互相覆盖），含：

- `manifest.json` —— 格式版本 v2、逐文件 sha256、每个会话的 header（id/cwd/创建时间/父会话/agentPreset/标题/行数/帧数）+ **稳定身份 `remoteId`** + `maxSeq`/`lastTime`/`blank` + 本机 `deviceId` + 导出告警
- `goal/**` —— 目标目录整棵树（goal.json、draft.json、讲义 `NN-*.md`、问答 `NN-qa.md`、回写补充 `NN-notes/**`，以及会话 AI 在工作区里写的任何文件）
- `sessions/<会话id>/transcript.jsonl.zstd` —— **逐字节原文**，含该工作区目录下的全部会话（目标会话、每章会话、子代理会话、已归档会话）
- `attachments/objects/<xx>/<sha256>` —— 会话正文引用的图片对象（内容寻址）
- `workspace.json` —— 仅该目标的工作区登记信息（参考用）

**不含**：你的凭据与设置（`settings.yaml` / `.credentials.yaml`）、日志、皮肤、profile 插件本体、`session_projcache.json`（自愈缓存）、其它目标的数据、本目标的 `.mnemon/` 记忆、以及**设备本地身份账本** `.study-sync.json`。

**导入 = 应用一个包（可重复执行，不会越导越多）**。三种模式（面板上三选一，默认「⤴ 覆盖」）：

| 模式 | 目标已存在 | 会话已存在 | 用途 |
| --- | --- | --- | --- |
| **⤴ 覆盖** | 更新它（逐文件按 sha 比对后写入） | 内容一致⇒不动；包更新⇒**只追加尾帧**；包更旧或两边分叉⇒需要你勾「允许覆盖」(force) | 日常同步、换机恢复、把备份盖回来 |
| ➕ 合并 | 更新它，但只新增与快进 | 分叉项**不动**（报 `skippedDiverged`） | 不敢丢本地历史时 |
| 📋 另存副本 | 换新 goalId 新建 | 会话全部换发新身份 | 并排对比、实验、同一包导两次要两份 |

1. 先「🔍 预览这个包」：看清落点、**分类计数**（新增 / 追加尾帧 / 整份替换 / 不变 / 回退 / 分叉 / 被挡）、每条会话将用什么身份、以及冲突与提示；
2. 模式或 force 一改动会自动重新预览；
3. 无阻塞 → 「✓ 确认覆盖导入」（或合并/副本对应文案）；
4. 导入做的事：还原/更新目录树 → 会话落进本机项目目录（**只重写 header 帧**，必要时换发新会话 id）→ 附件按内容寻址回写（`attachmentId` 不变）→ 重映射 `goal.json` 里的会话 id → 合并 `index.json` → 复用或重建工作区登记并把会话挂回去、顺手摘掉幽灵席位 → 写 `.study-sync.json` 身份账本；
5. 写完先按宿主自己的视图自检：每条会话 `inspect()` 读得懂 **且** 出现在工作区投影里；任一不过 ⇒ **整体回滚**（还原被覆盖的字节、删掉自建目录、恢复索引与工作区登记），不会再出现「导入成功却看不见」；
6. 全局 `storages/workspace.json` 不会被覆盖；本地比包多的文件不会被删除（本次刻意不做 prune）；
7. 导入/迁移后建议**重启 DSH** 再看左栏分组（宿主缓存在启动期定型）；若会话仍不在该目标分组里，点该目标的「🔗 重新绑定会话」（它同样以宿主投影判定成败，失败会明确告诉你哪条不显示）。

**为什么导入有时会给会话换一个新 id**：宿主把会话 id 当作**全局身份**——同一个 id 不能同时存在于两个项目目录（否则整个会话列表会报错），而且「归档」状态也按 id 全局记录（这个版本还没有"取消归档"）。所以跨机器、跨目录、或该 id 曾被归档时，导入会自动换发新 id 并把 `原身份 → 新身份` 记进目标目录的 `.study-sync.json`；下次同步靠它认出同一个会话，重复导入同一个包就是「无改动」。

**跨机须知**：会话正文里的旧绝对路径（以及正文里提到的旧会话 id）按设计**保留**——那是历史文本，只重写 header。继续学习不受影响，新写入的内容都用新路径。`manifest.json` 里有源机绝对路径、用户名与 `deviceId`，公开分享前先看一眼。

## 3. 会话模型（怎么学）

1. **目标总会话**：负责调研与讲义生成，别在这里学习。想改课程草案时在这里让 AI 直接重写 `draft.json`。
2. **章节会话**：点「开始学习」进入后，AI 以本章讲义开场（读讲义 → 目标与要点概览 → 等你提问，逐点讲解）。每次回答后，如果 AI 发现回答中有讲义未覆盖的有价值补充内容（新示例、新角度、易错点、实战技巧等），会询问你是否要回写——回复「回写」即可。回写采用**「总结入讲义 + 详细独立文件」**模式：讲义中只插入一行带链接的总结（如 `> 💡 [补充：xxx](NN-notes/slug.md) — 核心要点`），详细内容存放在 `chapters/NN-notes/` 目录下的独立文件中；同一主题多次回写会在同一文件中累积扩展。你说「结束」时它总结本章并把问答要点写入 `NN-qa.md`。多轮问答沉淀在学习内容里，可随时再进该会话继续问。
3. **主聊天**：管理进度/目标（见 §4）。学习本身在目标/章节会话里发生。

> 设计上无测验、错题本与「已学完」标记：学完一章后仍显示「讲义就绪」，随时可重学。

## 4. 聊天里直接管理

直接输入自然语言即可，例如：

- 「看看我的学习进度 / 学到哪了」→ 各目标进度与下一步建议
- 「帮我建一个学 XX 的计划（目标：能…；要求：中文讲义）」→ 建目标；随后按提示打开一次目标会话，再说「开始调研」
- 「开始调研 / 重新调研」→ 在目标会话内发起/重发联网调研
- 「草案可以，批准」/「草案不行，改成 XX」→ 批准或退回
- 「把软件设计这个目标导出/备份」→ 生成 zip 并告诉你落盘路径
- 「用 `D:\bak\study-goal-….zip` 导入」→ 先给预览（分类计数：新增/追加尾帧/不变/需 force）；你说确认再写入。要覆盖已存在的目标说「用覆盖模式导入」，内容分叉时它会明确要你说「带 force」；想留两份说「另存为副本导入」
- 「再把这个包导一次」→ 若已是最新，返回「无改动」（幂等），不会多出一份副本

## 5. 数据在哪里

全部在 `C:\Users\pyg12\.dsh\study-work\`：

- `plugin/` — 插件安装快照（恢复用）

## 6. 重启之后怎么办（恢复）

DSH 进程重启后，动态插件会丢失，但**所有学习数据、工作区与目标/章节会话都保留**：

1. 重开 GUI（本会话或其他会话），对助手说：**「按 C:\Users\pyg12\.dsh\study-work\plugin\INSTALL.txt 恢复学习插件」**；
2. 助手读取快照 `study-plugin.dist.json`，重新定义并激活插件（客户端需在 GUI 点一次批准）；
3. 学习区入口恢复，旧目标直接出现在列表中，点「打开会话」可继续之前的学习。

也可让助手直接从项目仓库重装：`C:\Users\pyg12\gitProjects\study_dsh_plugin`（见该仓库 INSTALL.md）。

## 7. FAQ

- **章节一直「生成中」**：点「继续生成」；若提示先打开会话，就点该目标的「📄 打开会话」后再继续。
- **「重新调研」后还是旧草案**：新版退回会清空草案文件，不会复现旧草案；如仍显示，点 ⟳ 刷新。
- **批准后想改课程**：退回草案 → 在目标会话里让 AI 修改并重写 `draft.json` → 重新批准。旧讲义文件不会被自动删除。
- **删除目标会不会删文件**：不会，仅移出列表并标记 deleted。
- **目标一直「调研中」却什么都没发生**：看 chip——写**「待调研」**说明指令从没发过（从聊天创建的目标都是这样），展开点「▶ 开始调研」即可；写**「调研中…（派发于 HH:mm）」才是 AI 真在跑**。若红字说「代理未激活」，先点「📄 打开会话」再点一次。
- **每次点「打开会话」会不会多出一个会话**：不会。面板优先回到 `goal.json` 里记录的目标总会话；只有它被销毁（或从未建立）时才新建并回写 id。若你手动删除了该会话，下次点击会自动重建。
- **点「打开会话」报「打开会话失败: … is not a function / 连接会话的方法不存在」**：v0.3.1 已修。原因是宿主把浏览器侧的 `connectWorkspace` 从 `workspaces` 服务迁到了 `uiWorkspace` 服务，旧插件照旧名字调用就会撞上不存在的方法（症状时有时无：只有目标会话需要新建时才走这条路）。v0.3.1 起按「方法是否存在」三段兜底 `uiWorkspace` → 旧版 `workspaces` → 直接 `sessions.create`，全都没有也只给白话提示。**升级到 v0.3.1 并重启 DSH 即可**；若仍报错，说明宿主又改了服务名，请把面板红字原文反馈给我。
- **测验/错题/复习入口在哪**：已按需求移除，学习闭环 = 讲义 → 独立会话教学与多轮问答 → 写回 NN-qa.md。
- **导入后左栏能看到目标文件夹，但会话不见了**：v0.2.x 的缺陷，v0.3.0 已修。原因是宿主把会话 id 当**全局身份**（同 id 不能出现在两个目录，否则整个会话列表报错；归档状态也按 id 记录且这版无法取消），旧实现照抄源 id ⇒ 要么"导入即隐身"，要么把列表打爆。现在导入会按需换发新 id 并记进 `.study-sync.json`，且**写完就按宿主投影自检**，不认账就整体回滚。老数据补救：用 v0.3.0 重新导入一次该包（选「覆盖」）即可。
- **会不会越导越多份会话/目标**：不会。同一个包重复导入是幂等的（面板显示"已是最新（无改动）"）；只有你主动选「📋 另存副本」才会新建一份目标并给它所有会话换发新身份。
- **导入说"分叉/包更旧"，不给覆盖**：这是保护——本地会话比包新（你这边又学了），或两边各写了不同内容。确认可丢弃本地内容再勾「允许覆盖分叉/更旧的本地会话」；不确定就先「➕ 合并」（只快进、不动分叉项），或先把当前目录复制一份留底。
- **提示某条会话"按宿主规则不会单独出现"**：那是空会话（从没发过消息，宿主列表本来就不显示）或子代理会话（挂在父会话下展开），不是丢了。
